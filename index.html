CUSTOMER JOURNEY MAP SKILL · CLAUDE CODE / CODEX

Agent 懂代码。
懂用户吗？

代码在 repo 里，agent 读得到。人的体验不在。
Journey 把它记成 .journey/ 里的一张旅程地图，放在代码旁边。
聊着就能建，需求变了按 diff 改，证据和猜测分开标。

安装 Journey ↗看它如何工作 ↗
YOUR CODE HAS A MAP.
SO SHOULD YOUR USERS.
BUILD IN CONVERSATION · UPDATE BY DIFF · EXPRESS FOR ANY AUDIENCELOCAL FILES · OPEN SOURCE
01 / WHAT YOU CAN DO

说清楚场景。
地图交给 Journey。

不用先学字段，也不用选模板。
从你手头的一段经历、访谈或产品笔记开始。

01 / BUILD

把对话整理成地图

“梳理用户第一次申请这份工作的经历。”

按里程碑和步骤建立结构，连接人的目标、行为、情绪与触点。留下可继续编辑的旅程文件。

02 / UPDATE

改需求，接着改地图

“现在允许跳过注册，会影响哪些步骤？”

修改相关步骤与引用，记录改了什么、为什么改。下一次对话从已有地图继续。

03 / EXPRESS

同一份理解，交给不同的人

“给评审会一张地图，给工程师一份交接。”

从同一份旅程生成交互视图、简报、故事线或规格说明，按读者需要组织信息。

02 / INSPECT THE MAP

看得到步骤。
也查得到判断的来处。

下方直接读取仓库的求职示例。
15 个步骤、分支与字段都可以逐项检查。

JOB APPLICATION / MAYA打开地图，查看原始字段 ↗
断点说明：AI 筛选未记录情绪，不代表中性或零分。横向看阶段，纵向看体验 · 点击打开完整地图

在项目里，持续保存

Markdown 旅程保存在 .journey/，能进版本控制，也能在后续会话里接着用。

把推断和依据分开

来源标记保留判断来处。缺少依据的内容，可以被找到、追问和补充。

修改前后，有迹可循

脚本写入前检查结构与引用，变更记录保留操作与备注。

03 / WHY IT MATTERS

测试通过了。
人为什么还在门外？

一条提前十五分钟预订的规则，一间空着的会议室。跟着两个人走一遍，看看需求遗漏了什么。
