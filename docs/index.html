DOCUMENTATION / GET STARTED

从第一段对话开始。

Journey 是放在 coding agent 里的用户旅程 skill。你描述人的目标和遇到的问题，它帮助整理成一份能持续更新的地图。

01　安装到你的环境

需要 Git，以及能读取对应 skills 目录的 Claude Code 或 Codex。选择你的环境，把命令粘贴到终端执行。

git clone --depth 1 https://github.com/cguodesign/customer-journey-map-skill ~/.claude/skills/journey

安装后，在项目里开始一段关于用户体验的对话。

如果对应目录已经存在，请先检查现有安装。不要用新 clone 覆盖你已有的修改。安装后在目标项目中开启新会话，让 agent 读取 skill。

02　讲清楚一个人的目标

可以从现有访谈、产品说明或一段具体经历开始。无需先挑字段，也不必提前画完整流程。

使用 journey skill，帮我梳理新用户第一次使用产品的旅程。
先问我必要的问题；把已知事实和你的推断区分开。
从用户的目标、行为和感受开始。

没有真实资料时，也可以先建立草稿，但应当把假设保留下来，等后续观察来确认。

03　找到留下来的地图

旅程通常保存在项目的 .journey/ 目录中。检查 agent 回报的路径，确认文件已经写入。

your-project/
└── .journey/
    ├── onboarding.md    # 里程碑、步骤和来源
    └── onboarding.log   # 通过脚本写入的变更记录

它是你拥有的本地文件，可以放进版本控制。后续对话可以继续读取和修改这份旅程。

04　试着修改一次，再换个视角

我们现在允许用户跳过手机号验证。
请更新对应步骤，说明影响了哪些后续行动。
然后把新旅程生成一个适合评审的交互地图。

你可以要求查看修改、检查缺少的依据，或把旅程表达为简报和工程交接。

常见问题

需要先学会服务设计或字段名称吗？

不需要。先讲清楚场景、人的目标和你掌握的信息，字段随需要出现。字段参考用于深入检查和自定义表达。

地图保存在什么地方？

本地项目中的 .journey/ 目录。无法写文件的环境可以在对话里返回内容，由你保存。具体位置应以 agent 的实际回报为准。

能自动证明某个需求是对的吗？

不能。结构校验检查字段与引用，来源记录帮助追溯判断。真实体验仍然需要研究和验证。

可以用 Notion 或 Drive 多人同时编辑吗？

当前产品以个人在项目中持续维护理解为主。共享存储、多输入合并等团队能力仍在规划中。

安装后还需要运行什么服务吗？

Journey 不是独立的托管服务。它包含 skill 指令、模板和 shell 工具；写入、校验等脚本需要相应的 shell 环境，HTML 输出可在浏览器查看。
